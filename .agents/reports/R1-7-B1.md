### 9 · Not done, and why
The 4 STOP files were not migrated because doing so would rewrite `findUnique({ where: { email } })` to include `tenantId`, blinding the uniqueness check to accounts in other tenants and allowing duplicate email registration across the global user table:
1. `src/app/api/tenant/accountant/route.ts:72`: `prisma.user.findUnique({ where: { email } })`
2. `src/app/api/tenant/employees/route.ts:109`: `prisma.user.findUnique({ where: { email } })`
3. `src/app/api/tenant/employees/[employeeId]/route.ts:43`: `prisma.user.findUnique({ where: { email } })`
4. `src/app/api/tenant/users/route.ts:87`: `prisma.user.findUnique({ where: { email } })`
Per STOP condition 1, these 4 files remain on the allowlist for the Planner to decide the platform door (e.g. `platformDb().user.findUnique(...)`).
