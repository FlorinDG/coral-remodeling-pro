## 2 · Canonical Rules & Intent Construction

- **Only Changed Fields:** In accordance with §R2-1, writers no longer spread `{ ...page.properties, x }`. The intent carries strictly the delta:
  ```typescript
  const intent: RecordIntent = {
      pageId: id,
      databaseId: dbId,
      fields: { status: 'opt-paid' }, // only changed fields
      baseUpdatedAt: page.updatedAt,
  };
  ```
- **Door Choice by Call Site:**
  - Authenticated user actions (actions, portal setup, scan, quotes): `await scopeFromSession()`
  - System background processes (cron, Peppol inbound, backfill): `systemScope(tenantId, reason)`
  - Client portal endpoints: `portalScope(access)` (never a raw tenant id)
- **Refusals Handled, Never Swallowed:**
  - `EXPORT_LOCKED`: Refuses edit if row has been exported to accountant (`accountantExportedAt`).
  - `DOCUMENT_LOCKED`: Refuses edit if invoice/quote is finalized.
  - `STALE_WRITE`: OCC version mismatch.
  - `NOT_FOUND`: Target record does not exist.
  Each caller reports or logs the refusal explicitly.

## 3 · Testing Strategy & Throw Proofs

For each module:
1. Extract any business logic into pure helper functions where applicable.
2. Unit tests using `node:test` covering:
   - Successful save through `saveRecord`
   - Correct `by` tag recorded in audit trail
   - Rejection on refusal (`EXPORT_LOCKED`, `STALE_WRITE`)
3. Throw proof per module: intentionally inject an invalid `intent` or mutate refusal handling → assert test fails → restore.
