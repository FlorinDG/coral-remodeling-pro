# CORAL — NICE-TO-HAVE / FUTURE BACKLOG (Planner-maintained)

Parking list for good ideas that are **not needed now** — revisit when scale/need justifies them. Not in the active coder queue.

| # | Item | What / why | Trigger to revisit |
|---|------|-----------|--------------------|
| 1 | **Neon Read Replicas** | Read-only compute endpoint on Neon's shared storage — offload heavy reads (reports/analytics/dashboards) off the primary. Cheap on Neon (no data copy). NOT worth it now: low traffic, and replica lag would worsen the current persistence-staleness issues. | When the live dashboard / analytics or heavy reporting starts competing with the transactional DB. |
| 2 | **User-automation RULE ENGINE** | Generic "trigger → condition → action" builder that powers all user automations from one system (vs hand-coding each). Real paid-tier differentiator, but a big upfront build. Deferred (Florin 2026-07-12): hand-code the few high-value automations into Settings first; extract the engine once the real trigger/action shapes are proven. | After 3–4 hand-coded automations reveal the common pattern, or when users start asking for custom rules beyond the built-in set. |

| 3 | **Excel-style `=` formulas in engine number fields** | In the engine's calculated fields, type `=` then a basic arithmetic expression (`= 12*3 + 5/2`, parentheses) and it evaluates on blur/Enter — Excel-style quick math. **Basic arithmetic only** (`+ - * / ( )`), no cell references, no functions. Clean insertion point: every numeric input already routes through one util `parseDecimal` (`lib/decimal-parser.ts`); extend it to detect a leading `=`, safely evaluate the expression (a tiny hand-rolled tokenizer/shunting-yard — **NOT `eval`/`Function`**), and return the result. Every field inherits it. Small, self-contained, low-risk. | Any time — small win; pick up on a light day or when doing engine polish. |

| 4 | **Attachments thumbnail/grid view** | The `RecordAttachments` panel (shared — quote/invoice engines + all detail surfaces) lists each file as a **full-width row**, so a long attachment list is very space-inefficient. Add a **thumbnail/grid view** (image/PDF-first-page previews in a compact grid) with a toggle between list and grid. Benefits every surface that uses the panel, not just quotations. Reuse the `/api/files/<key>` serving route for the preview src. | Any time — small UI win; bundle with a document/engine polish pass. |

| 5 | **Proper rich-text editor (TipTap/Lexical)** | Both rich-text surfaces — the engine's "Vrije Tekst" block and the journal editor — are **hand-rolled `contentEditable` + deprecated `document.execCommand`**, which is fragile (see the reset bug `VRIJETEKST-EDITOR-RESET`, and the "journal editor horror story" `JOURNAL-EDITOR-REWORK`). Replacing both with ONE proper editor lib (**TipTap** — ProseMirror-based, React-friendly, actively maintained; or Lexical) fixes the whole class: stable controlled state, real formatting, paste handling, extensibility. Fixes the free-text block AND the journal in one move. | When doing the journal rework, or after the immediate `VRIJETEKST-EDITOR-RESET` fix — upgrade the underlying editor rather than keep patching execCommand. |

| 6 | **Document edge-detection + auto-capture scanner** | Camera front-end that detects the paper edges and auto-snaps when the frame is stable + in focus → far better capture quality → better OCR → smaller manual review pile. Options: **Veryfi Lens for Browser** (same vendor as our OCR, turnkey capture→OCR) — but **NOT cheap** (Veryfi Pro ~€0.08/scan, or a Growth plan; no quote requested yet), so deferred as not crucial. Free alternative: **OpenCV.js/jscanify** edge detection + a **docuSnap-style** auto-capture (rolling-buffer, pick sharpest frame) — free, ~8 MB WASM (lazy-load in the scan flow only), DIY logic. Plugs into `SCAN-MOBILE-CAMERA-FALLBACK`. | When receipt/scan volume makes capture quality the bottleneck, or if Veryfi Lens cost is justified after a quote. Do the OpenCV.js path if going free. |

| 7 | **Payroll export to social secretariat (Partena)** | Parked by Florin 2026-07-26: **Partena Professional runs their own platform and the hand-off is done manually there**, so an export format has no destination today. Timesheet reporting therefore ships with **XLSX + PDF werkbon only** (`coral-timesheet-reporting.md` TS-4). | If Partena exposes an import template/API, or if the manual re-keying volume becomes painful enough to justify producing their layout. |

| 8 | **checkin@work / aanwezigheidsregistratie — RESEARCH ONLY** | Belgian statutory on-site presence registration for works above a threshold. **The ERP cannot substitute for it** — the system requires physical, on-site registration on external infrastructure, so workers on those projects clock **twice** (theirs + ours) and that is accepted. Florin deliberately structures work to stay **under the threshold** ("a huge headache"). **Do not build, do not claim compliance, do not surface it in the UI.** The ONLY thing worth investigating, and only if it ever becomes relevant: whether a **REST API exists to DOWNLOAD registrations** so they could be imported one-way into our timesheets (never the reverse). Research first, build never-by-default. | Only if Florin takes on a project above the threshold AND the double-entry becomes costly. Start with an API-availability check, not a build. |
