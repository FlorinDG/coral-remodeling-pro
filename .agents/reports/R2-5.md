# 8 · 🟨 Report-only items
### Server write doors inline Prisma analysis
The four write doors contain inline Prisma calls without separated pure decision engines:
1. `saveGlobalPage` (`src/app/actions/global-databases.ts:69-158`):
   - Concurrency check at lines 80-92 is reachable as a pure function if extracted: `checkPageOCC(existing, incoming)`.
   - Property merge at lines 99-106 is reachable as a pure function if extracted: `mergeProperties(existingProps, incomingProps, dirtyBase)`.
   - Not reachable in pure unit tests without Prisma: the inline `prisma.globalPage.findFirst`, `prisma.$transaction`, and `prisma.globalPage.update`.
2. `saveGlobalPagesBatch` (`src/app/actions/global-databases.ts:160-205`):
   - Iterates array sequentially calling `saveGlobalPage` for each item. Pure behavior is sequential execution with individual conflict reporting.
3. `createPageServerFirst` (`src/app/actions/pages.ts:17-64`):
   - Does not perform OCC check; assigns `blocksVersion: 1` unconditionally.
4. `updatePageServerFirst` (`src/app/actions/pages.ts:66-107`):
   - Accepts no `baseUpdatedAt` parameter and performs blind unconditional `prisma.globalPage.update`.

### Recommended exports for future pure testability
- `src/app/actions/global-databases.ts:80`: export pure `evaluatePageOCC(existing: { updatedAt: string, blocksVersion: number }, incoming: { baseUpdatedAt?: string, blocksVersion?: number, dirtyBaseBlocks?: boolean })`
- `src/app/actions/global-databases.ts:100`: export pure `mergePageProperties(existingProps: Record<string, any>, incomingProps: Record<string, any>, dirtyBase?: Record<string, any>)`
