## 3 · 🔴 Found: the ERP merge loses data — fix on `pending/occ-merge`
**What happens today (every record: quotes, invoices, projects, tasks):**
1. **Silent overwrite.** A and B open the same record. B changes field X and saves. A changes field Y and saves on the older version. The server's merge writes **A's old X over B's change** — no warning. (`global-databases.ts` merge: "client unchanged, server changed" fell into the "take the client's value" branch.)
2. **False "Sync Conflict".** After a first successful save the store kept an empty base (`{}`), so every later concurrent edit of another field read as "both changed". This is very likely part of the OCC "over-fires" history.

**The fix (branch, 2 commits):**
- `lib/records/occ-merge.ts` — ONE merge rule, both save doors call it (it was copied inline twice). Per field against the base: only I changed → mine; only they changed → **theirs kept**; both, differently → conflict; derived totals → my recomputation. **No base → the old strict rule** (any difference = conflict) — a client without a base is never silently merged.
- The save returns the fields it kept (`keptServer`); the browser adopts them (unless edited again meanwhile) — otherwise its next save would write the stale value back.
- A clean page has **no** base (the next edit snapshots a full one) — also stops clean pages being kept in IndexedDB as "dirty" forever.
- Tests on the REAL code: 7 merge + 2 store; the coder's copy tests removed.

**How to test (2 minutes, preview of `f12fcff`):** two browsers (or one + private window), same quotation. Browser 1 changes the title and saves. Browser 2 (not refreshed) changes "betreft" and saves. → Both changes survive; no conflict dialog. Today on production: browser 2 silently puts the old title back.

**Risk:** this is THE save path of the ERP. Behaviour changes only for a stale save (two people on one record); a normal single-user save is untouched. Not promoted — yours to decide. R2 (one write path) would have needed this anyway; it is R2-2 ("field-level intents") in its smallest form.
